## Project architecture

- Keep this MVP frontend-only with mocked browser data (tracker counts), because real sync and accounts will be integrated later. The exception is Agzos AI (4.0): it calls Groq for real, but only from the main process (`electron/ai.cjs`); the API key goes once to `ai:set-key`, lives only encrypted by `safeStorage` (`<userData>/ai-key.bin`, refused when the OS has no keyring) and never returns to the renderer, logs or state files. The web preview has no AI.
- Persist browser state only through `src/features/browser/persistence/` (`BrowserStore`): the web preview uses localStorage (`agzos-state`), the desktop app uses SQLite in the main process (`electron/db.cjs`, `node:sqlite`, no native modules). Schema changes go in as new entries of `MIGRATIONS`; never edit an applied migration.
- Browser actions live in `src/features/browser/commands.ts`; shortcuts, the web context menu and the native Electron menu (`electron/main.cjs`) all use those command IDs. Tab state changes go through the pure reducer in `store/reducer.ts`.
- Every file the main process `require`s must be listed in `ELECTRON_FILES` in `scripts/build-all.sh`, which ships `electron/*.cjs` without `node_modules`. The only exception is `node-pty` (terminal, 4.0): an N-API native module that `copy_pty` in `build-all.sh` ships per platform into `resources/app/node_modules/node-pty`. Do not add other native modules.
- Before pushing, run `bun run lint`, `bun run typecheck`, `bun run test` and the e2e suites (`bun run test:e2e:web`; `xvfb-run -a bun run test:e2e:desktop` on Linux without a display). Plans per version live in `docs/prd/`.
- Keep Electron isolated under `electron/`, load a prepared static bundle from `dist/`, and preserve context isolation with Node integration disabled for desktop security.
- Network interception goes through the single per-session pipeline in `electron/main.cjs` (`session-created`): Electron keeps only one listener per `webRequest` event, so never register a second `onBeforeSendHeaders`/`onHeadersReceived`/`onBeforeRequest`; extend the existing ones. Adblock lives in `electron/adblock.cjs`; its engine is bundled into `electron/adblocker.vendor.cjs` by `bun run desktop:build`.
- Keep the Chrome identity in `electron/main.cjs` (`applyChromeIdentity`, `chromePageShim`, session Client Hints): without it Google rejects sign-in inside tabs. Read `docs/login-google-desktop.md` before changing it.
- Site permissions live in `electron/permissions.cjs` (SQLite `site_settings`, per origin). The permission _check_ handler must keep answering "allowed" for anything the user did not explicitly block: Google sign-in depends on it (see `docs/login-google-desktop.md`).
- The main process supports several windows: per-window state lives in a `ctx` (views, active tab, panel, fullscreen) found through `event.sender` in every IPC handler, and tab ids are per window (`tabOfContents` maps a page's `webContents.id` to its window and tab). Never reintroduce a global "main window"; broadcast app-wide events (downloads, adblock stats, updates) to every window. Window sessions and bounds live in `electron/windows.cjs` (`meta:windows`), not in the renderer's `session` section; shared sections are relayed to the other windows (`agzos:state-sync`).
- Toolbar panels (⋯ menu, downloads, privacy, site, bookmark, key) render in a transparent per-window `WebContentsView` above the page (`electron/chrome-overlay.cjs`, `dist/overlay.html`, `src/features/browser/overlay/`), so the page keeps painting; never hide the tab or `capturePage` for them. The shell sends a `PanelSpec` (data + function names) and the layer calls the shell back. The snapshot path is only the fallback, and it is still used for the omnibox list, the what's-new dialog and the non-layer switcher.
- 2.0 (workspaces, tab groups, split view, side panels): tabs carry `groupId`/`workspaceId` and the per-window session also stores `groups`, `workspaces` and `split` (`electron/windows.cjs` `validSession` passes them through; the renderer validates in `persistence/snapshot.ts`). The tab strip, Ctrl+Tab, Ctrl+1…9 and "close others" only see the active workspace (`workspaceTabs`). Split view: the main shows the two tabs of `ctx.split` with per-pane rects (`tab:bounds` with an id, `tab:split`); focusing the other pane emits a `focused` tab event. Side panels are per-window `WebContentsView`s in the default session (`sidepanel:*` IPC, `sidePanelOwner` for `ownerCtx`), laid out with the tabs and hidden with the snapshot fallback or fullscreen.
- Tab hibernation (`electron/hibernate.cjs`) closes a hidden tab's `WebContentsView` and restores it with `navigationHistory.restore`; keep its skip rules (audio, capture, pending permission, edited forms) when touching it.
- GX Control (3.0) is a shell panel (`src/features/control/`) fed by `gx:*` IPC; its rules live in `electron/gx-control.cjs`. The CPU limiter only changes the throttling rate through the debugger the tab already has attached; never attach/detach it there. The RAM limiter goes through `hibernateTab`, so the hibernation skip rules still apply.
- Side panels (3.1.1) use `zoomMode: "isolated"` with the factor per app in `meta:sidePanelZoom`, so their zoom never touches the tabs' per-host zoom; Ctrl +/−/0 go through `wireShortcuts(..., { zoom })`. Before quitting or closing a window, `releaseSidePanels` unloads each panel page (`about:blank`) and flushes storage (Discord writes its token on `beforeunload`); keep that path when touching quit/close, and never clear panel storage. Pure rules live in `electron/panel-session.cjs`.
- Every release adds an entry at the top of `src/features/browser/changelog.ts` with the version `scripts/build-all.sh` publishes: the "Atualizado com sucesso" dialog shows it after the update.
- Auto-update lives in `electron/updater.cjs` and reads the `latest.json` written by `scripts/release-browser.sh`; it never deletes files in the install folder (copies over it) and only runs packaged or with `AGZOS_UPDATE_URL`.
- 4.0: GPU switches are applied in `electron/gpu-flags.cjs` before `app.whenReady()` (after the test `userData` override); keep its crash fallback (three GPU process crashes → next start without forced flags). Gestures are detected in `electron/page-preload.cjs` (tabs, and side panels with `--agzos-surface=panel`, where the login watch is off) and mapped to actions in the shell (`src/features/gestures/run.ts`, prefs `gestures`); keep its thresholds in sync with `src/features/gestures/gestures.ts`. The terminal (`electron/terminal.cjs`, `src/features/terminal/`) never writes to a shell on open; with the terminal focused, only the combos in its `BROWSER_COMBOS` (and ⌘ on the Mac) stay with the browser.
- 4.1 terminal: sessions belong to the window `ctx` and survive any view change (bottom, right, floating `terminal.html`); views attach with `terminal:list` (output history replay), so never kill sessions on unmount. Terminal events go through `sendTerminal` (shell and floating window). API keys for terminals live only in `electron/terminal-secrets.cjs` and reach shells via `extraEnv`; never send them to a renderer. Aliases go through generated init files (`electron/terminal-launch.cjs`); SSH args come only from `sshArgs`. The microphone is granted only to the app's own UI (`isAppInterface`).
- 4.1.1: CLI install recipes and agent invocations live only in `electron/cli-install.cjs` (fixed recipes, never text from the renderer; agent prompts go as argv, no shell). Files the Chromium can't render open through `agzos-file://` (`electron/files.cjs`), which requires the per-user token (`meta:fileToken`); keep its pages script-free. PWAs (`electron/pwa.cjs`) run in `persist:pwa-<id>` with their own permission keys; the app holds a single-instance lock so shortcuts (`--agzos-pwa=<id>`) reach the running instance. Tests use `AGZOS_TEST_HOME` and `AGZOS_TEST_PWA_CONFIRM`, both ignored in packaged builds. Files the OS hands over (argv on first launch and `second-instance`, `open-file` on macOS) go through `filesOfArgv` + `openSystemFiles`.
- 4.1.3: PWA installability no longer requires a service worker; the manifest is read through CDP `Page.getAppManifest` (fallback: fetch in the tab session), the page preload watches `<link rel=manifest>` added later, and `pwa:check` backs Settings → "Tentar instalar este site como app". Agzos AI conversations, projects, open tabs and persona live in `electron/ai-library.cjs` (meta `aiChats`; the 4.0 `aiHistory` migrates into the first chat); the shell only gets summaries (`ai:library`) and asks for messages per chat (`ai:messages`). Answers render through `src/features/ai/markdown.ts` (React elements, never raw HTML); artifact previews are `srcdoc` iframes without `allow-same-origin`, and the media permission is refused to sub-frames of the app UI.
- 4.5: Session Tabs use `persist:agzos-session-<id>` (`tabPartition` in `electron/main.cjs`); the tab carries `session: { id, color }`, links and duplicates inherit it (`tab/open-page` with `from`), and partitions no saved window uses are removed at startup (`electron/session-tabs.cjs`). Ports panel: `electron/ports.cjs` (pure parsing of `ss`/`lsof`/`netstat`) and `electron/ports-service.cjs`; kill only PIDs from the last scan, never the app's own. HTTPS tunnel only through a `cloudflared` binary found on PATH or picked by the user (`electron/tunnel.cjs`); never download or bundle one; tunnels die with the panel, the window or the app. The inspector (`electron/inspector.cjs`, world 4132) and the reader extractor (`electron/reader.cjs`, world 4133) run in isolated worlds and build DOM without `innerHTML`; reader output goes through `cleanArticle` and renders as React elements. The reader and the expanded side panel hide the tab view in the main (`ctx.covered`, `ctx.sidePanelExpanded` in `isShown`). Scratchpad capture uses the tab's existing debugger (`Network.enable`/`disable`, `electron/scratchpad.cjs`); resend goes through the tab session, http(s) only. Extensions (`electron/extensions.cjs`, `electron/crx.cjs`) load only into the default session (not private or Session Tabs); Web Store `.crx` is unpacked by our zip reader with path checks. Widevine only exists in the castLabs ECS Electron (`components`), which `scripts/build-all.sh` downloads; VMP signing runs only when `castlabs_evs` is set up. Clipboard in Electron 44 is async (`clipboard.write([new ClipboardItem(...)])`). Notes are the `notes` BrowserStore section (key from `noteKeyOf`); Notes and Agzos AI share the right dock (opening one closes the other).
- 4.6: shell menus that need app styling (Ferramentas, the extensions pop-up and each extension's menu) are overlay panels (`tools`, `extensions`, `extmenu` in `OVERLAY_KINDS` and `PanelView`), never native menus. Extensions load from a per-extension copy in `<userData>/ExtensionsRuntime/<sha1(dir)>` (stable id) whose manifest gets `exclude_matches` for hosts without access; the user's unpacked folder is never modified. Extension pop-ups are a frameless `BrowserWindow` in the default session, measured after load (max-content width, then height) and right-aligned under the anchor; they close on blur unless DevTools is open. The reader notebook in the URL bar shows only after `readerProbeScript` (isolated world 4133) reports a readable article for the current URL. Sidebar width is the `sideBarWidth` pref (`sideBarLayout` picks compact/normal/wide and icon/font sizes); the resize handle reuses the side panel drag through the main (`sidepanel:drag`).
- 4.6.1: Web Store CRX3s carry two proofs (the author's and Google's, which is the same for every extension); `parseCrx(buffer, storeId)` keeps only the key whose id is the store id, else error `proof`, so never take the first key. Updates only notify (`checkUpdates` → `update` field and badge); install them only on `extensions:update`. The extension click follows the manifest (`kind`: popup, sidepanel, options, background); the extension menu only lists items the manifest has. Extension pop-ups are a new window per opening, destroyed on close, and re-measured while the page builds (`POPUP_MEASURE`, `popupPlacement`). Toolbar tooltips are the app's (`electron/tooltip.cjs` and `useBarTooltips`), not native `title` tooltips.
- 4.7: downloads manager is the shell page `agzos://downloads` (Ctrl+J; the toolbar button keeps the quick panel). Routing, tags and exports are pure in `electron/download-rules.cjs` (config in meta `downloadsConfig`, migration 5 adds `tags`/`etag`/`last_modified`/`url_chain`); removals and clears are broadcast to every window. Page theme (`electron/page-theme.cjs`) is CSS through `insertCSS` per registrable domain (meta `pageThemes`, private tabs in memory) plus a read-only script in isolated world 4134; never inject page-world scripts for it. ColorTools: the eyedropper is a `data:` layer view over the tab showing a compositor capture that answers through its title (`electron/color-tools.cjs`), the analyzer runs in isolated world 4135; history and palettes are the `colors` BrowserStore section. PDF Tools (`src/features/pdf/`, lazy-loaded) runs pdf-lib (`@cantoo/pdf-lib`, AES-256) in an inline worker and pdf.js with an inline worker; the OCR assets ship in `dist/ocr` (copied by `prepare-build.cjs`) and reach the shell only through `pdf:ocr-asset` (the shell is `file://`, no fetch). `electron/pdf-tools.cjs` only overwrites files the user opened and writes into folders the user picked; AI summary and cloud copy stay off until enabled and confirm per file. Tabs run with `plugins: true` (Chromium PDF viewer). Feature shortcuts are configurable (`prefs.features.shortcuts`); the main forwards them from pages via `shortcuts:extra`.
- 4.7.1: never ask a page whether it is in Picture-in-Picture. `pipContents` (a WeakSet) is the single source of truth, filled by the `enterpictureinpicture`/`leavepictureinpicture` events the page preload forwards over `agzos:pip`; the hibernation check and the GX Control read it without touching the page. It used to run `executeJavaScript` once per frame per minute inside `checkHibernation`, which held the main process and froze the sidebar and the navigation. Because the events come from the page, PiP started by the site's own player is tracked too, not just the toolbar shortcut.
- 4.7.1: the floating terminal (`openTerminalPip`) is a plain window, not an always-on-top one. It goes behind the browser when you work on a tab and comes forward when you click it; do not re-add `alwaysOnTop`/`setAlwaysOnTop`. Bounds still persist in `meta:terminalPipBounds`.
- 4.7.1: the `second-instance` listener is registered at module load, right after `requestSingleInstanceLock()`, and buffers argv in `pendingSecondInstances` until the app is ready. Registering it inside `whenReady` lost the event whenever the user clicked a PWA shortcut while the app was still starting, and the fallback then showed the browser window — the only visible symptom. When a PWA id is present, either open the app or log; never fall through to the browser window. The macOS PWA `.app` must not set `LSUIElement` (it hid the app from the Dock).
- 4.8: feature flags per PRD block live in `electron/feature-flags.cjs` (code default < build `agzosFlags` < user meta `featureFlags` < `AGZOS_FLAGS`, which only works unpackaged); runtime capabilities are measured once per Electron/Chromium in `<userData>/capabilities.json` (`electron/capabilities.cjs`), never with `offscreen: true` (it crashed the main with the overlay layer open). DevTools (flag `devtools`, on by default) docks per tab in its own `WebContentsView` (`electron/devtools-dock.cjs`): the shell reserves the area and sends `devtools:bounds`, and opening/closing/side always come from the shell, which knows the side saved per workspace (meta `devtoolsDock`). Open docked with `mode: "right"`/`"bottom"` (not `"detach"`, which hides device mode). A hook in the frontend keeps it `undocked` (compact, no page placeholder) and docks it only while device mode is on; then, as in Chrome, the frontend covers the page area plus the dock and the tab goes to the bounds it asks for (`setInspectedPageBounds`, relayed with a per-dock token over the frontend's `console-message`), with the panel sized to the dock (`setSidebarSize`). Undocked, the frontend opens its own `device_mode_emulation_frame` window: the frontend's `setWindowOpenHandler` denies it. With an external frontend `isDevToolsOpened()` is false, so hibernation and the GX Control ask `devtoolsDocks.isOpen`. Before opening detached, the external frontend must be destroyed (otherwise Electron reopens inside it), and never call `openDevTools` inside a `destroyed` handler (SIGTRAP). The mira card reaches the main through a per-tab token on `console-message` (the isolated world has no IPC).
- 4.8.3: on macOS each installed PWA is its own app: `~/Applications/Agzos Apps/<name>.app` is an APFS clone (`cp -c`) of `Agzos Browser.app` with its own `CFBundleIdentifier` (`br.agzos.browser.pwa.<id>`), name, icon and an ad-hoc signature, built by `buildMacPwaApp` in `electron/pwa-mac.cjs` (execFile only, never a shell; `xattr -cr` before `codesign`, never `--deep`). Keep `CFBundleName` and the executable name: Electron finds its helpers through them. Bundles that symlink the browser's `Frameworks` crash at startup, so do not "optimize" the clone into symlinks. The clone runs `main.cjs` in host mode (`pwaHost`, read from `Contents/Resources/agzos-pwa.json` before the single-instance lock): profile `<userData>/PwaApps/<id>`, only the app window, quits with it, links go to the browser through `--agzos-open=<url>`. The browser rebuilds clones of another version on start (`refreshMacPwaApps`). `AGZOS_TEST_PWA_HOST` points a marker in tests (ignored when packaged). Flag `pwa_mac_apps`.
- Release pipeline: the only source of the release notes is `src/features/browser/changelog.ts`; `scripts/release-notes.ts` renders the entry of the version being published and `scripts/build-all.sh` fails early if that entry is missing, so `latest.json` can no longer carry notes of another release. From 4.7.1 the canonical artifact name is `Agzos-Browser-*` (the old `Agnos-Browser-*` was a typo that became a contract): `release-browser.sh` links the name that actually exists in each published directory (`pkg_name`), because the KEEP=2 policy keeps the pre-4.7.1 directory with the old name next to the new one.
