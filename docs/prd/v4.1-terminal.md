# Agzos Browser 4.1.0: terminal em qualquer lugar, voz, IA, SSH e aliases

**Versão:** 4.1.0
**Base:** 4.0.0

## Objetivo

Deixar o terminal da 4.0 pronto para o dia a dia: escolher onde ele fica, ajustar a
aparência, falar comandos, abrir ferramentas de IA e servidores SSH com um clique, e ter
aliases e atalhos próprios.

## Decisões de arquitetura

- **Nada roda sozinho.** Sem aliases a sessão sobe como na 4.0. Com aliases, só os arquivos de inicialização gerados (declarações de alias/função) entram; ferramentas de IA e comandos rápidos só rodam quando o usuário clica.
- **Segredos só no main.** As chaves de API e a da Groq nunca voltam para a casca: a UI vê os nomes. Nomes de sistema (PATH, LD_PRELOAD, NODE_OPTIONS…) são recusados.
- **SSH sem injeção de opção.** Host e usuário passam por lista de caracteres e não podem começar com `-`; os argumentos vão em array para o `ssh` (sem shell).
- **Microfone só para a interface do app.** O handler de permissão aceita áudio para a casca e o terminal flutuante; páginas seguem o fluxo normal. macOS: `askForMediaAccess` e `NSMicrophoneUsageDescription` no Info.plist.
- **Terminal flutuante é da janela.** As sessões continuam com a janela dona (`terminalPipOwner`); fechar a janela fecha o PiP; fechar o PiP só esconde o terminal.
- **Lançador dentro do terminal.** Menus não podem abrir acima do painel (a página nativa cobriria); o lançador abre por cima da tela do próprio terminal.

## Testes

- Unitários: `src/features/browser/v41.test.ts` (aliases e bash real com alias e chave no ambiente, SSH seguro, chaves SSH, cofre de chaves, transcrição multipart, preferências e atalhos).

## Pendente de validação manual

- PiP e microfone no Windows e no macOS (permissão do sistema na primeira vez).
- Aliases no PowerShell/cmd e zsh do macOS; detecção das ferramentas quando o PATH do app (aberto pelo Dock/Finder) é menor que o do shell.
