# PRD v1.5.0: Navegador de verdade

> Roadmap: [`docs/roadmap-opera-vivaldi.md`](../roadmap-opera-vivaldi.md), itens NAV-001, NAV-002, NAV-006, NAV-007 e NAV-013.
> Base: v1.4 (publicada como 1.3.4). Status: **implementado** no branch `claude/kind-newton-8xs54n` (resultados na seção 8).

## 1. Objetivo

Entregar os recursos que mais pesam na percepção de "navegador de verdade", com o menor esforço:

- o escudo passa a **bloquear anúncios e rastreadores de verdade** (hoje os números são simulados);
- **downloads** com progresso, pausar, retomar, cancelar, abrir e mostrar na pasta;
- **buscar na página** (Ctrl+F) com "3 de 12";
- **zoom por site** (Ctrl +/−/0), lembrado entre reinícios;
- os **atalhos** que qualquer usuário de Chrome espera.

A identidade visual da Agzos continua a mesma: os elementos novos usam os mesmos tokens, painéis e botões da 1.4.

## 2. Fora de escopo

- Histórico, favoritos com pastas e omnibox com sugestões (1.6).
- Filtros cosméticos avançados (scriptlets, `:has()` procedural, filtragem de HTML). A 1.5 aplica só o bloqueio de rede e o CSS de ocultação.
- Escolher as listas de filtros na interface. A 1.5 usa um conjunto fixo, que pode ser trocado por variável de ambiente.
- Recursos reais na versão web. Lá o navegador roda num `iframe` e não tem acesso à rede das páginas, aos downloads nem ao `findInPage`. A web continua funcionando e informa que o recurso é do app desktop.

## 4. Desenho técnico

```
electron/
  main.cjs               # + downloads, find, zoom, atalhos; liga o adblock nas sessions
  adblock.cjs            # listas, cache, worker, onBeforeRequest, contagem por aba, CSS
  adblock-worker.cjs     # worker_thread: texto das listas → motor serializado
  adblocker.entry.cjs    # entrada do bundle (não vai no app)
  adblocker.vendor.cjs   # gerado no desktop:build (gitignored), vai no app
  downloads.cjs          # DownloadItem → registro, nome único, eventos
  zoom.cjs               # degraus de zoom (puro)
  db.cjs                 # + migrations v2 (downloads) e v3 (site_settings), meta
src/features/browser/
  commands.ts            # + comandos novos; Shortcut ganha mod/alt
  store/…                # + blocked, zoom, find (runtime), downloads
  ui/find-bar.tsx
  ui/downloads-panel.tsx (em src/features/downloads/panel.tsx)
```

**Pipeline de rede.** O Electron aceita um único listener por evento de `webRequest` em cada session. A identidade de Chrome já usa `onBeforeSendHeaders` e `onHeadersReceived`; o adblock usa só `onBeforeRequest`. O registro dos três fica junto, no `session-created`, com um comentário de que qualquer recurso novo precisa entrar nessas mesmas funções.

**Qual aba fez a requisição.** `details.webContents` → mapa `webContents.id → tabId`. Requisições sem `webContents` (service workers) são filtradas mas não contadas. A janela da casca (`file://`) nunca passa pelo filtro.

**Categoria.** Dois motores: `ads` (EasyList + EasyList Brasil) e `privacy` (EasyPrivacy). Verifica `privacy` primeiro. Custo medido: ~55 µs por requisição.

**Variáveis para testes.** `AGZOS_FILTER_LISTS` (JSON `{ ads: [url], privacy: [url] }`) e `AGZOS_DOWNLOADS_DIR`.

## 6. Riscos

| Risco                                                            | Mitigação                                                                                    |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Segundo listener de `webRequest` apagaria a identidade de Chrome | Só `onBeforeRequest` é novo; teste e2e de identidade continua na suíte                       |
| Parse das listas trava a janela (~0,6 s)                         | Worker thread; o main só desserializa (~5 ms)                                                |
| Sem rede no primeiro boot                                        | O app funciona sem bloqueio e tenta de novo no próximo boot; o cache antigo continua valendo |
| Filtro quebra um site                                            | "Pausar neste site" libera tudo naquele host                                                 |
| `node_modules` não vai no app                                    | Bundle único gerado no `desktop:build`, listado em `ELECTRON_FILES`                          |

## 7. Mudanças de comportamento e bugs achados pelos testes

- O escudo deixa de mostrar números simulados. O selo mostra requisições bloqueadas na página; o painel lista os hosts por categoria; a página inicial mostra o total real do dia. Na versão web os números ficam em 0 e o painel explica que o bloqueio é do app desktop.
- "Salvar como…" (Ctrl+S) agora abre o diálogo nativo e aparece no painel de downloads. O menu da página ganhou "Salvar link como…", "Abrir imagem em nova guia", "Salvar imagem como…" e "Copiar imagem".
- **Bug evitado:** navegar até a URL de um arquivo deixava essa URL no histórico da aba, e ao restaurar a sessão o arquivo era baixado de novo. Agora a aba continua na página em que estava (como no Chrome); se não havia página antes, ela vira uma aba nova.
- **Bug evitado:** com um download em andamento o Electron não encerrava ao fechar a janela. Agora os downloads ativos são cancelados no `before-quit` e ficam como "Cancelado" na lista.
- **Bug evitado:** pausar o site e recarregar logo em seguida ainda bloqueava, porque a configuração do escudo só chegava ao main depois do debounce de 300 ms. Agora ela vai direto por IPC (`adblock:config`).
- Alt+←/→, Ctrl+Tab, Ctrl+1…9, F5, F11 e as demais teclas da tabela também funcionam com o foco dentro da página.

## 9. Extras pedidos durante a 1.5

### Ctrl+Tab em ordem de uso (estilo Opera/Vivaldi)

- Toque rápido volta para a última aba usada; repetido, alterna entre as duas últimas.
- Segurando o Ctrl aparece o seletor com miniaturas reais (tiradas da aba visível depois de carregar, ao ativar e ao sair de cena). Tab/Shift+Tab andam, soltar o Ctrl confirma, Esc cancela, clique escolhe.
- O main repassa o Ctrl/⌘ solto mesmo com o foco dentro da página (`agzos:modifier-up`).
- Ctrl+PageDown/PageUp e Ctrl+1…9 seguem a ordem da barra, como no Chrome.

### Abas animadas, tachinha e vidro

- Hover com destaque em vidro; na horizontal a aba encolhida volta ao tamanho cheio e a fixada abre e mostra o título depois de uma pausa.
- Tachinha: selo animado no ícone das abas fixadas.
- Barra vertical recolhida: pausar o mouse abre uma espiada. Ela empurra a página em vez de flutuar, porque o `WebContentsView` fica por cima da casca.
- Painéis, menus, seletor e barra de permissão em vidro, com entrada suave.

### Revisão com a skill `ui-ux-pro-max`

Buscas usadas: estilo `glassmorphism`, UX de foco, hover, tempo de animação, contraste e alvos de clique, e o `quick-reference` (prioridades 1, 2 e 7). O design system da Agzos (vermelho, Manrope, tokens) foi mantido; a skill serviu de checklist.

| Regra da skill                                           | O que mudou                                                                                                |
| -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `aria-labels`, `icon-context`                            | A aba tem nome acessível próprio ("github.com, fixada, anônima…"): nas fixadas o título fica escondido     |
| `keyboard-nav`                                           | Lista de abas no padrão WAI-ARIA: setas, Home/End e Delete para fechar                                     |
| `escape-routes`                                          | Esc fecha qualquer painel aberto                                                                           |
| `focus-states`                                           | Anel de foco em todos os controles próprios da casca; fixar/fechar aparecem com o foco, não só com o mouse |
| `hover-vs-tap`                                           | Nada importante depende só de hover: fixar/fechar também pelo teclado e pelo menu de contexto              |
| `web-target-size`                                        | Alvos de clique com pelo menos 24×24 px (fechar, fixar, estrela, zoom, atualizar listas)                   |
| `motion-consistency`, `exit-faster-than-enter`, `easing` | Tokens únicos: entrada 220 ms desacelerando, saída 140 ms acelerando                                       |
| `press-feedback`, `scale-feedback`                       | Clique encolhe levemente botões e abas                                                                     |
| `stagger-sequence`, `modal-motion`                       | Cartões do seletor entram em sequência (30 ms); painéis crescem a partir de quem os abriu                  |
| Glassmorphism: "vibrant background verified"             | Brilho discreto do vermelho Agzos atrás da barra de abas, para o vidro ter o que desfocar                  |
| Tipografia (texto < 12 px é antipadrão)                  | Nenhum texto de interface abaixo de 11 px (havia 8, 9 e 10 px nos painéis)                                 |
| `reduced-motion`                                         | Já existia: `prefers-reduced-motion` zera animações e transições                                           |

Exceção consciente: `transform-performance` pede para não animar largura. A expansão da aba no hover e a espiada da barra vertical animam largura porque o pedido é justamente a aba/barra crescer e empurrar o conteúdo (a página nativa não pode ficar por baixo de um overlay).
