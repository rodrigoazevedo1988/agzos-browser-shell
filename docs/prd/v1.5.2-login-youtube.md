# PRD v1.5.2: Login do Google e anúncios do YouTube

> Base: 1.3.6. Será publicada como **1.3.7**.
> Origem: teste real da 1.3.6 no Windows 11: login recusado mesmo com o site pausado no
> escudo ("0 bloqueados"); anúncios no YouTube. Painéis e guias verticais resolvidos.

## 1. Login do Google: causa real

O shim da identidade de Chrome (`window.chrome.app/csi/loadTimes`, sem o qual o Google
recusa o login) era registrado por CDP antes da primeira navegação, **sem `Page.enable`**.
Nesse modo o Chromium aplica o script só ao primeiro documento da guia. Medido no app
(Electron 44, Xvfb):

| Versão                   | 1ª carga | Recarga   | Mesma origem | Outra origem |
| ------------------------ | -------- | --------- | ------------ | ------------ |
| 1.3.3 (commit `33c3244`) | ok       | **vazio** | **vazio**    | **vazio**    |
| 1.3.4                    | ok       | **vazio** | **vazio**    | **vazio**    |
| 1.3.6                    | ok       | **vazio** | **vazio**    | **vazio**    |
| 1.3.7 (`Page.enable`)    | ok       | ok        | ok           | ok           |

Ou seja: o login só funcionava quando `accounts.google.com` era a primeira página da guia
ou abria num popup. Pelo "Fazer login" do google.com (navegação na mesma guia) sempre
falhou, no Windows e no Mac. O adblock da 1.3.5 agravava (bloqueava a telemetria do
antifraude), mas não era a causa principal.

## 2. Correções

| Item                                 | Correção                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Identidade de Chrome em toda carga   | `Page.enable` ao conectar o debugger (`applyChromeIdentity`)                                                                                                                                                                                                                                                                                               |
| Logins intocados (pedido do usuário) | `isAuthUrl`: `accounts.*`, `login.*`, `auth.*`, `sso.*`, `id.*`…; caminhos `/login`, `/signin`, `/oauth`, `/authorize`, `/saml`…; provedores (Google, Apple, Microsoft, Okta, Auth0, OneLogin, Duo, Cognito, gov.br). Nessas páginas: sem filtro de rede, sem scriptlets, sem CSS de ocultação, sem leitura do DOM                                         |
| Sem preload nas páginas              | O `tab-preload.cjs` da 1.3.6 saiu. Scriptlets entram por CDP (`addScriptToEvaluateOnNewDocument`), só nos sites com regras, registrados antes do `loadURL` (espera de no máximo 300 ms) e guardados por hostname                                                                                                                                           |
| YouTube                              | Listas oficiais do uBlock Origin (uAssets), no lugar do espelho do Ghostery, que estava atrasado (`quick-fixes`: 496 × 580 linhas). Entram as regras atuais contra anúncio inserido pelo servidor (`trusted-replace-*`, `trusted-rpnt`). YouTube passa de 29 para 36 scriptlets. Listas renovadas a cada 24 h (antes 7 dias), com checagem de hora em hora |

## 3. Descobertas no caminho

- Script registrado por CDP **no meio de uma navegação** não vale para aquele documento; por
  isso os scriptlets são registrados antes do `loadURL`.
- Toda gravação de estado (debounce de 300 ms) reenviava as preferências; os scriptlets só
  são refeitos quando o escudo ou os sites pausados mudam de fato.

## 4. Limites

- Não foi possível completar um login real do Google neste ambiente de testes (a política de
  rede bloqueia `www.gstatic.com`). A causa foi medida no app e o teste e2e novo garante que
  o shim vale em toda carga.
- Na **primeira** carga de um site numa guia **nova**, o scriptlet às vezes chega depois do
  HTML (medido: 8 em 10 antes). Da carga seguinte em diante (recarga, próximo vídeo, links)
  roda sempre antes dos scripts da página (10 em 10). No YouTube a troca de vídeo é por
  `fetch`, que os scriptlets interceptam em qualquer caso.
- Anúncios do YouTube: mesma corrida do uBlock Origin. Com as listas oficiais e renovação
  diária o app acompanha o uBO, mas um anúncio novo pode passar até a lista seguinte.
