| #   | Recurso                      | Resumo                                                                                                     |
| --- | ---------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 1   | Várias janelas               | `Ctrl/⌘ N`, "Mover para nova janela", "Abrir link em nova janela"; cada janela com as suas guias           |

## 2. Várias janelas

**Como funciona:**

- Cada janela tem a sua casca (renderer) e as suas guias. O main guarda o estado por
  janela (`ctx`: guias, guia ativa, painel aberto, tela cheia…) e acha a janela de cada
  pedido pelo `event.sender`. Não existe mais "janela principal" (`mainWindow`).
- Os ids das guias continuam sendo de cada janela. O mapa `webContents.id → { ctx, id }`
  diz a quem pertence cada página. O adblock conta por `webContents.id`, que é único entre
  as janelas.
- Preferências, favoritos, atalhos da página inicial e "reabrir guia fechada" valem para
  todas as janelas. Quando uma janela grava, o main repassa para as outras
  (`agzos:state-sync`). Cada janela lembra o que já está no SQLite, então nada é regravado
  nem volta num pingue-pongue.

**Ações:**

| Ação                      | Onde                                                                                                             |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Nova janela               | `Ctrl/⌘ N`; menu da guia e da faixa de guias                                                                     |
| Mover para nova janela    | Menu da guia (com mais de uma guia). A página vai viva, sem recarregar (o `WebContentsView` muda de janela)      |
| Abrir link em nova janela | Menu de contexto do link                                                                                         |
| Fechar uma janela         | Com outras abertas, as guias dela são descartadas (como no Chrome)                                               |
| Sair do app               | Todas as janelas voltam no próximo início. No Mac, fechar a última janela e clicar no Dock reabre a janela salva |

- A janela nova abre em cascata a partir da atual. Posição e tamanho de cada janela (e se
  está maximizada) voltam no próximo início, desde que caibam numa tela conectada.
- O título da janela (barra de tarefas, Alt+Tab) segue a guia ativa.

## 3. Sessão restaurada após crash

**Gravação contínua:**

- Janelas, guias e posições ficam no SQLite (`meta:windows`, `electron/windows.cjs`) e
  são gravadas a cada mudança, não só ao sair.
- A casca grava com no máximo 1 s de atraso, mesmo com páginas carregando sem parar: num
  crash se perde no máximo esse tanto.
- A seção `session` da 1.6 (uma janela só) vira a primeira janela na primeira execução.

**Marcador de execução (`meta:running`):**

- É gravado ao abrir e apagado na saída normal. Se ainda existe no início seguinte, o app
  não fechou direito (crash, falta de energia, processo encerrado).

| Situação                                                   | O que acontece                                                                                                                                                         |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fechamento inesperado depois de 1 min aberto               | Janelas e guias voltam; faixa "O Agzos não foi fechado corretamente…"                                                                                                  |
| Caiu no primeiro minuto (provável travamento ao restaurar) | **Modo seguro**: as guias voltam, mas a ativa de cada janela é uma "Nova aba". Nenhuma página carrega sozinha; faixa "O Agzos fechou logo depois de abrir…"            |
| Casca de uma janela caiu (renderer)                        | Recarrega sozinha (até 3 vezes). As páginas continuam vivas no main e a casca volta com a sessão da janela; guias que ela não conhece mais são fechadas (`tabs:known`) |

## 4. Telas de erro

- O Chromium deixa a página em branco quando a carga falha (`did-fail-load` sem
  `did-navigate`). Agora o main esconde a página e a casca mostra a tela certa. A tela sai
  quando uma navegação dá certo.
- `ERR_ABORTED` (Esc, outro link, download) não é erro.

| Erro                                                 | Tela                                        | Ações                                                                                                 |
| ---------------------------------------------------- | ------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `ERR_INTERNET_DISCONNECTED`, `NETWORK_CHANGED`       | Sem conexão com a internet                  | Tentar novamente; recarrega sozinha quando a rede volta                                               |
| `ERR_NAME_NOT_RESOLVED`                              | Não foi possível encontrar este site        | Tentar novamente; Pesquisar o endereço no buscador                                                    |
| `CONNECTION_REFUSED/RESET/CLOSED`, `EMPTY_RESPONSE`… | Este site não pode ser acessado             | Tentar novamente; Voltar                                                                              |
| `TIMED_OUT`                                          | O site demorou demais                       | Tentar novamente                                                                                      |
| Certificado (`-200` a `-299`)                        | Sua conexão não é particular                | Voltar para a segurança; Avançado → Continuar (não seguro): só nesta execução, por host e certificado |
| `ERR_BLOCKED_BY_CLIENT`                              | O escudo bloqueou esta página               | Permitir este site (pausa o escudo no host)                                                           |
| `TOO_MANY_REDIRECTS`                                 | Ciclo de redirecionamentos                  | Tentar novamente                                                                                      |
| Página travou (`render-process-gone`)                | Pelo motivo: sem memória, encerrada, travou | Recarregar                                                                                            |
| Página sem resposta (loop)                           | Faixa "Esta página não está respondendo"    | Esperar; Encerrar página                                                                              |

Cada tela mostra o código do Chromium (ex.: `ERR_CONNECTION_REFUSED`), como o Chrome.

## 5. Hibernação de guias

**Regra:**

- Guia sem ser vista há 30 minutos (15, 30, 60 ou 120 nas Configurações; dá para
  desligar) tem a página fechada.
- A guia continua na faixa, esmaecida ("hibernada para economizar memória").
- Ao abrir, a página é recriada com o histórico de navegação (`navigationHistory.restore`:
  voltar/avançar e posição da rolagem).

**Não hiberna** (as mesmas regras do "Economia de memória" do Chrome):

- a guia visível;
- guia tocando som;
- guia carregando;
- guia usando câmera ou microfone;
- guia com pedido de permissão aberto;
- guia em tela cheia;
- guia com DevTools aberto;
- guia com **formulário preenchido** (conferido na página, num mundo isolado).

**Detalhes:**

- **Manual:** "Hibernar guia" no menu da guia (não vale para a ativa).
- **Sites com scriptlets do adblock (ex.: YouTube):** a preparação com `about:blank`
  impede o restore. A guia volta só com a página atual, como uma guia nova.
- **Guias restauradas ao abrir o app:** as que não estão à vista aparecem como hibernadas.
  Elas já não carregavam antes de serem abertas; agora isso fica visível.

## 6. Arquivos

| Arquivo                                     | Papel                                                                                                           |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `electron/windows.cjs`                      | Registro das janelas (sessão, posição), marcador de execução, modo seguro, posição válida                       |
| `electron/hibernate.cjs`                    | Regras da hibernação, histórico restaurável, detecção de formulário preenchido                                  |
| `electron/main.cjs`                         | Estado por janela, IPC por `event.sender`, janelas novas, mover guia, falhas de carga, certificados, hibernação |
| `src/features/browser/load-errors.ts`       | Texto de cada erro de rede e de travamento                                                                      |
| `src/features/browser/ui/error-page.tsx`    | Tela de erro                                                                                                    |
| `src/features/browser/ui/notice-bars.tsx`   | Faixas "página sem resposta" e "sessão restaurada"                                                              |
| `src/features/browser/persistence/store.ts` | Sincronização entre janelas (`subscribe`, `syncPayloadOf`)                                                      |

Os dois `.cjs` novos entram em `ELECTRON_FILES` do `build-all.sh`.
