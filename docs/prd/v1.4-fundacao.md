# PRD v1.4.0: Fundação

> Roadmap: [`docs/roadmap-opera-vivaldi.md`](../roadmap-opera-vivaldi.md), itens FND-001, FND-002 e FND-003.
> Base: v1.3.3. Status: **implementado** no branch `claude/v1.4-fundacao` (resultados na seção 8).

## 1. Objetivo

Preparar o código para as próximas versões (adblock, downloads, histórico, workspaces, split view) **sem mudar o que o usuário vê**. Ao final da 1.4:

- cada recurso novo entra num módulo próprio, sem mexer num arquivo de 1300 linhas;
- o app desktop guarda o estado em SQLite, com migrations versionadas;
- existe uma rede de testes (unitários, web e Electron) e um CI que roda em todo PR.

## 2. Fora de escopo

- Recursos novos visíveis (histórico, favoritos com pastas, downloads e adblock ficam para a 1.5 e a 1.6).
- Auto-update (FND-004 fica na 1.6).
- Mudança de layout ou de identidade visual.
- Qualquer alteração na identidade de Chrome (`applyChromeIdentity`, `chromePageShim`, Client Hints).

## 3. Requisitos

### FND-001: Store e componentes

| ID        | Requisito                                               | Critério de aceite                                                                                                                                           |
| --------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| FND-001.1 | Estado de abas num reducer puro (`store/reducer.ts`)    | Todas as ações de aba (abrir, fechar, fechar outras/lados, duplicar, fixar, mutar, reabrir, navegar, voltar/avançar) cobertas por testes unitários sem React |
| FND-001.2 | IDs de aba sequenciais (`nextId`)                       | Duplicar, restaurar ou abrir várias abas no mesmo milissegundo não colide                                                                                    |
| FND-001.3 | Registro central de comandos (`commands.ts`)            | Atalhos de teclado, menu de contexto web e menu nativo do Electron usam os **mesmos IDs de comando**                                                         |
| FND-001.4 | Sync com o desktop num único módulo (`desktop-sync.ts`) | Aba removida do estado → `closeTab` no main; aba ativa → `activateTab`; painel → `setPanelOpen`. Não há chamadas ao bridge espalhadas pelos componentes      |
| FND-001.5 | `chrome.tsx` dividido em componentes                    | `chrome.tsx` cai de 1317 para ~420 linhas e só compõe; os componentes de UI ficam abaixo de ~200 linhas                                                      |
| FND-001.6 | Paridade visual                                         | Screenshots antes e depois idênticos na página inicial, abas verticais e painéis                                                                             |

### FND-002: Camada de dados

| ID        | Requisito                                                                 | Critério de aceite                                                                                                             |
| --------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| FND-002.1 | Interface `BrowserStore` (`load`/`save` de um snapshot versionado)        | O renderer não chama `localStorage` diretamente                                                                                |
| FND-002.2 | Web: adapter em `localStorage` numa chave única `agzos-state` (schema v1) | Dados das chaves antigas `agzos-*` migram no primeiro load, e as chaves antigas são removidas                                  |
| FND-002.3 | Desktop: SQLite no main (`electron/db.cjs`) com `node:sqlite`             | Sem módulo nativo (o `build-all.sh` não empacota `node_modules`). Arquivo `userData/agzos.db`, WAL, tabela `schema_migrations` |
| FND-002.4 | Migração do desktop                                                       | No primeiro boot da 1.4, o estado salvo no `localStorage` do app (1.3.x) vai para o SQLite                                     |
| FND-002.5 | Validação                                                                 | Snapshot corrompido ou de outro formato não derruba o app: campos inválidos caem no padrão                                     |
| FND-002.6 | IPC seguro                                                                | `state:load`/`state:save` só aceitam as seções conhecidas, com limite de tamanho. Sem SQL vindo do renderer                    |
| FND-002.7 | Privacidade                                                               | Abas anônimas nunca vão para o disco, nem para a lista de "reabrir guia fechada"                                               |

## 4. Desenho técnico

```
src/features/browser/
  chrome.tsx              # compõe: Titlebar, Toolbar, TabRail, Viewport, painéis
  store/
    state.ts              # tipos BrowserState + estado inicial
    reducer.ts            # reducer puro das abas e preferências
    selectors.ts          # activeTab, orderedTabs, canBack/canForward…
  commands.ts             # registro de comandos (id, rótulo, atalho, run)
  use-hotkeys.ts          # teclado → comando
  desktop-sync.ts         # eventos do main → dispatch; estado → bridge
  menus.ts                # layout dos menus de contexto web a partir dos comandos
  omnibox-input.ts        # texto digitado → URL/busca (puro)
  persistence/
    snapshot.ts           # schema v1, parse/validação, migração das chaves antigas
    store.ts              # BrowserStore: localStorage (web) e SQLite via IPC (desktop)
    use-persistence.ts    # load inicial + save (imediato na web, debounce 300 ms no desktop)
    use-credentials.ts    # cofre Agzos Key (inalterado, só extraído)
  ui/
    tab-item.tsx, tab-list.tsx (faixa + rail), toolbar.tsx, viewport.tsx, permission-bar.tsx
electron/
  main.cjs                # + state:load/state:save, AGZOS_USER_DATA para testes
  db.cjs                  # node:sqlite, migrations, kv
```

**Snapshot v1**

```ts
type Snapshot = {
  version: 1;
  prefs: { dark; engine; shield; aiOpen; orientation; railCollapsed; pausedHosts };
  session: { tabs: Tab[]; activeId: number };
  links: QuickLink[];
  closedTabs: ClosedTab[];
};
```

No desktop cada seção é uma linha da tabela `kv` (`key`, `value` JSON, `updated_at`). As próximas versões adicionam tabelas próprias (`history`, `bookmarks`, `downloads`) por migration.

**Credenciais** continuam fora do snapshot: `safeStorage` no desktop e a chave `agzos-credentials` na web, como na 1.3.

## 6. Riscos

| Risco                                                | Mitigação                                                                                                         |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `node:sqlite` é experimental no Node 24              | API estável o suficiente para `kv`; isolada em `db.cjs`, troca simples se necessário. Validado no Electron 44.4.5 |
| O `build-all.sh` copia só `main.cjs` e `preload.cjs` | Passa a copiar `electron/*.cjs`                                                                                   |
| Regressão de comportamento no refactor               | Testes e2e escritos contra o comportamento da 1.3.3                                                               |
| Perder dados do usuário na migração                  | A migração só apaga as chaves antigas depois de salvar no destino com sucesso                                     |

## 7. Mudanças de comportamento (correções)

- Fechar outras guias ou guias à esquerda/direita **não coloca mais abas anônimas** na lista de "reabrir guia fechada". Antes, a URL anônima ia para o disco.
- Fechar a última aba passa a permitir reabri-la com Ctrl+Shift+T.
- Ctrl+Shift+D também funciona com o foco dentro da página (desktop).
- **Bug corrigido:** na versão web o menu de contexto das abas não executava nenhum item. O `pointerdown` em captura fechava o menu antes do `click` chegar. Achado pelos testes e2e.
- Novo atalho Ctrl+Shift+N para nova aba anônima (vem de graça com o registro de comandos).
- Favoritar (estrela) não grava mais aba anônima nos atalhos da página inicial.
- O navegador reabre na aba que estava ativa, e não mais sempre na primeira.
- Endereços `localhost`/`127.0.0.1` digitados sem esquema abrem em `http://` (antes viravam busca).
